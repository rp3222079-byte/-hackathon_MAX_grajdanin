# Как устроен «Домовой»

## Схема

```
сайт-источник ──> парсер ──┐
                           ├──> база данных ──> REST API ──┬──> бот MAX ──> житель
житель (бот/сайт) ─────────┘                               └──> сайт
                                                            │
                                    обращение ──> SMTP ──> почта управляющей компании
```

Четыре процесса, одна база:

| Процесс | Команда | Что делает |
|---|---|---|
| API и сайт | `uvicorn app.main:app` | REST API и статические страницы |
| Бот | `python -m app.bot.main` | диалоги в MAX и рассылка уведомлений |
| Парсер | `python -m app.parser.runner` | собирает отключения с сайта по расписанию |
| Демо-данные | `python -m app.seed` | справочник УК и учебные отключения |

Бот не ходит в базу напрямую: он обращается к REST API (`app/bot/api.py`). Исключение —
рассылка уведомлений (`app/services/notifier.py`), ей нужен прямой доступ к таблицам,
чтобы не отправить одно и то же дважды.

## Ключевая часть: сопоставление адресов

Источник публикует адреса свободным текстом: `ул. Ленина, д. 1-15, 2, 4`. Житель вводит
свой адрес как умеет. Чтобы они сошлись, оба приводятся к паре ключей:

- `street_key` — улица без типа («ул.», «проспект») и без «ё»: `ленина`
- `house_key` — дом без «д.» и с корпусом через «к»: `12к2`

Диапазоны домов разворачиваются в отдельные записи `OutageArea`, поэтому поиск
затронутых жителей — это обычный индексированный запрос, а не перебор строк.

Логика: `app/services/addresses.py`, тесты: `tests/test_addresses.py`.

## Защита от дублей

- Отключение получает `fingerprint` — хэш из типа ресурса, адресов и времени начала.
  Повторный проход парсера по той же странице новых записей не создаёт.
- Уведомление фиксируется в таблице `notifications` с уникальной парой
  (пользователь, отключение). Одно и то же жителю не придёт дважды.

## Что упрощено ради хакатона

- Состояния диалогов бота хранятся в памяти процесса: после перезапуска
  незаконченный диалог теряется. На демо это незаметно, в проде нужен Redis.
- Вместо миграций — `Base.metadata.create_all`. Меняете модель — удаляете `domovoy.db`.
- Панель УК закрыта одним токеном из `.env`, без учётных записей сотрудников.
- Статус обращения меняется вручную в панели: обратной интеграции с почтой УК нет.
